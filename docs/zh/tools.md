# 工具集

本页是 Step Code 内置工具的参考手册：29 个工具的全景清单、文件/多模态/命令/联网/交互/编排各类工具的参数与行为边界，以及贯穿所有工具的通用机制（校验、结果回灌、并行调度、权限门控）。

工具由模型自行调用，你不需要手写调用语法。这份文档的用途是让你知道模型手里有什么、每个工具的边界在哪、出问题时该怀疑哪一层。

## 文件工具

前六个文件工具（`read_file`、`write_file`、`edit_file`、`list_dir`、`glob`、`grep`）都不依赖外部命令，走 Node 原生 API，因此在三个平台上行为一致。同属文件读取的 `read_media` 是例外：它需要解码图片，裁剪或降采样时懒加载第三方库 jimp，单独放在[多模态工具](#多模态工具)一节。路径参数统一处理：绝对路径直接用，相对路径以当前工作目录为基准。

### `read_file`

| 参数 | 类型 | 说明 |
|------|------|------|
| `path` | string，必填 | 文件路径 |
| `offset` | 正整数，可选 | 起始行号（1 起）。省略则从头读 |
| `limit` | 正整数，可选 | 读取行数。省略则读到末尾，受内部上限约束 |

每行以「行号 + TAB + 内容」返回，末尾附 `<system>` 状态块，写明已读行范围、总行数、是否截断。

行为边界：

- 单次最多返回 **2000 行**。`limit` 超过它按 2000 截。
- 不带 `offset` / `limit` 读整个文件时，文件超过 **256 KB** 直接报错，要求改用分页读。带了任一分页参数则不受这条限制。
- 传目录会报错并提示改用 `list_dir`。
- **图片会被挡下并引导去 `read_media`**：按扩展名（`.png`/`.jpg`/`.jpeg`/`.gif`/`.webp`/`.bmp`/`.ico`）或文件头魔数判定，命中即报错要求改用 `read_media`，不会让图片落到「文件过大请分页」这类误导文案上。
- 其余含 NUL 字节的文件按二进制拒绝。
- 空文件返回 `<system>文件为空（0 字节）。</system>`。

常见坑：状态块里的「已截断」既包括没读到尾，也包括 `offset > 1` 的情况——从中间开始读永远标截断。

### `write_file`

| 参数 | 类型 | 说明 |
|------|------|------|
| `path` | string，必填 | 文件路径 |
| `content` | string，必填 | 完整文件内容（整体覆盖） |

缺失的父目录会自动递归创建。成功返回写入字节数。

常见坑：这是**整体覆盖**，不是追加，也没有「只改一部分」的语义。对已有文件做局部修改要用 `edit_file`——用 `write_file` 覆盖意味着模型必须完整重写全文，长文件容易丢内容。

### `edit_file`

| 参数 | 类型 | 说明 |
|------|------|------|
| `path` | string，必填 | 文件路径 |
| `old_string` | string，必填 | 要被替换的原文，需逐字符匹配 |
| `new_string` | string，必填 | 替换后的内容 |
| `replace_all` | boolean，可选 | 是否替换全部匹配，默认 `false` |

行为边界：

- 默认要求**唯一匹配**。命中多处且未设 `replace_all` 时报错，并告知实际出现次数。
- `old_string` 与 `new_string` 相同时报错（无需编辑）。
- 找不到 `old_string` 时报错，提示先 `read_file` 确认原文。
- 文件不存在或读不出来报错，不会顺手创建。

**换行符容错**：模型生成的 `old_string` 通常是 LF，而 Windows 文件常是 CRLF，逐字符匹配会因 `\r` 失配。处理策略分三步：先按原样精确匹配；失配时把文件、`old_string`、`new_string` 三方都归一化成 LF 再匹配；写回时如果原文件出现过 CRLF，则整体恢复成 CRLF，不把 CRLF 文件污染成 LF。

#### 结果里的行级 diff

编辑成功后，除了 `已编辑 <path>（替换 N 处）。` 这行摘要，还会附一段行级 diff（实现在 `src/tui/diffView.ts`）。它用 LCS 逐行求差，再按「改动 + 少量上下文」聚类呈现：

- 首行是摘要 `+N -M path`（增删计数只在非零时出现）。
- 每簇改动前后各保留 **3 行**上下文；两处改动间隔在 6 行以内会并成一簇。
- 簇与簇之间用 `… N unchanged lines …` 省略。
- diff 主体上限 **40 行**，超出截断并附 `… N more changes hidden (Ctrl+O to expand)`，在 TUI 里按 Ctrl+O 展开完整输出。

diff 文本是纯文本、不含 ANSI，上色由渲染层按行首标记处理，所以它既能进 TUI 也能原样回灌给模型——模型能据此确认自己改对了地方。

### `list_dir`

| 参数 | 类型 | 说明 |
|------|------|------|
| `path` | string，可选 | 目录路径，默认当前工作目录 |

按名称排序返回，目录项带尾随 `/`。最多列 **500 项**，超出时附 `[共 N 项，仅显示前 500 项]`。空目录返回 `[空目录]`。

它**不递归**，也不过滤任何条目——`node_modules`、`.git` 会照常列出。要跨层级找文件用 `glob`。

### `glob`

| 参数 | 类型 | 说明 |
|------|------|------|
| `pattern` | string，必填 | glob 模式，如 `src/**/*.ts`、`*.md` |
| `path` | string，可选 | 搜索根目录，默认当前工作目录 |

固定忽略 `**/node_modules/**`、`**/.git/**`、`**/dist/**`。结果转成相对当前工作目录的正斜杠路径，排序后返回，上限 **200 条**，超出附计数提示。无匹配返回 `[无匹配文件]`。

常见坑：忽略列表是硬编码的三项，`.next`、`build`、`.cache` 这些不在内——在这类目录多的仓库里，结果可能被构建产物挤满 200 条上限。

### `grep`

| 参数 | 类型 | 说明 |
|------|------|------|
| `pattern` | string，必填 | 正则表达式（JavaScript 语法） |
| `path` | string，可选 | 搜索根目录，默认当前工作目录 |
| `ignore_case` | boolean，可选 | 忽略大小写，默认 `false` |

返回 `path:line:内容` 格式的匹配行，路径相对当前工作目录。

行为边界：

- 忽略目录：`node_modules`、`.git`、`dist`、`.next`、`build`、`.cache`。
- 目录递归深度上限 **20** 层；扫描文件数上限 **3000**。
- 单文件超过 **512 KB** 时改为流式逐行扫描；单行内容截断到 **1 MB**，并如实上报截断量。
- 匹配结果上限 **200** 条，达上限即停止扫描并附 `[结果已达上限 200 条，可能还有更多匹配]`。
- 含 NUL 字节的文件视为二进制跳过。

常见坑：正则用的是 JavaScript 语法，不是 grep 的 POSIX 语法——`\{` 之类的转义规则与命令行 `grep` 不同。正则非法时返回错误而非空结果。另外每行只报一次匹配，一行里多处命中不会重复列出。

## 多模态工具

### `read_media`

读本地图片文件，把图片内容以内嵌图片块回传给模型看。它是唯一让模型「看见」像素的工具，`read_file` 遇到图片只会把你导流到这里。

| 参数 | 类型 | 说明 |
|------|------|------|
| `path` | string，必填 | 图片文件路径 |
| `region` | 对象，可选 | 只看原图的某个矩形：`{x, y, width, height}`，原图像素坐标。先裁剪再按预算交付 |
| `full_resolution` | boolean，可选 | `true` = 跳过降采样按原图交付；原始字节超 4MB 时明确报错，建议改用 `region` 分块读 |
| `probe` | boolean，可选 | `true` = 只探测元数据（格式/尺寸/字节数/建议分块），不交付图片。读大图/长图前先 probe 拿精确尺寸与建议分块，避免盲目猜 `region` 报错 |

**能力门控**：模型的 `capabilities` 未声明 `image_in` 时，这个工具从工具表整个卸载，模型看不到、也就不会尝试调用——省掉一轮必然失败的往返。运行时还留了一层能力检查兜底。

行为边界：

- **读入硬上限 100 MB**：超过直接拒绝，不读进内存。
- **交付预算 4 MB**：超出则等比降采样后再交付。
- **长边上限 1568 px**：超出等比缩小（对齐主流视觉模型的推荐输入尺寸）。
- 不裁剪、不超预算时走**直通**：原始字节直接交付，不重新编码。
- **webp 需要裁剪或降采样时报错**：jimp 不支持重新编码 webp，此时提示你先转成 png 再读。未超预算的 webp 走直通路径，不受影响。
- `region` 超出原图范围时报错，并回报原图尺寸与你给的区域——同时**自动给出 clamp 后的可重试 region**（起点收进图内、跨度按剩余收窄），照着重试即成；或先用 `probe:true` 拿完整分块方案。
- **读大图/长图先 probe**：`probe:true` 只回元数据不交付图片，给出按交付上限切好的建议 region 列表（末块自动按剩余边界收窄，照抄不超界）。一张 30000px 的公众号长截图，probe 一次拿到约 20 个可直接使用的 region，替代「猜 region → 超界报错 → 再猜」的试错循环。
- 视频与音频 **v1 不支持**：按魔数嗅探识别（MP4/MOV/WebM/MKV/WAV 等），命中时明说「暂不支持读取视频/音频」，而不是笼统报「不是图片」。
- 图片解码失败（文件损坏或格式不支持）按错误结果返回。

裁剪或降采样时懒加载 jimp——只有真正需要解码才付出这个加载成本，直通路径不碰它。这也是它不能算进「文件工具都走 Node 原生 API」那条概括的原因。

另有一条**协议限制**：图片回传目前只在 `anthropic` 协议渠道端到端有效，`openai` 协议渠道的工具结果折叠只保留文本、图片会被静默丢弃（详见[配置参考](./configuration.md#capabilities-能力标签)）。

`read_media` 没有本地副作用，已归入只读工具集，任何权限档下都直接放行；计划模式下也不会被误拦——在 plan 里看界面截图正是典型场景。权限判定细节见下文[权限门控](#权限门控)。

## `bash`

执行一条 shell 命令，返回合并后的 stdout + stderr。

| 参数 | 类型 | 说明 |
|------|------|------|
| `command` | string，必填 | 要执行的命令 |
| `timeout` | 正整数，可选 | 前台超时秒数，默认 **60**，上限 **300**（超过按 300 计） |
| `run_in_background` | boolean，可选 | `true` 则后台执行并立即返回 task_id |

输出与退出码：

- 输出上限 **30000 字符**，超出保留头部并附 `[输出已截断，共 N 字符]`。运行期间内部收集上限 10 MB。
- 退出码非 0 时按错误结果返回，正文末尾附 `[退出码：N]`。
- 退出码 0 且无输出返回 `[命令执行完毕，无输出]`。
- 用户按 Esc 中断时杀掉进程并返回中断错误。

**前台超时不等于失败**：超时后默认不杀进程，而是把它收养进后台任务管理器、重新武装后台超时，工具正常返回一条说明（含已收集的部分输出）与 task_id，任务继续跑。关掉 `[background].bash_auto_background_on_timeout` 或上下文不支持后台任务时，退回旧行为——超时即杀并报错。

后台任务的查看与终止用 `task_list` / `task_output` / `task_stop`，见[子 agent 与自动化](./agents.md)。

### 跨平台 shell 探测

Windows 上没有现成的 POSIX shell，`bash` 工具按固定顺序探测解释器（实现在 `src/tools/shellResolve.ts`）：

1. 环境变量 `STEP_SHELL_PATH`（显式指定 bash 可执行文件绝对路径，最高优先）
2. PATH 里的 `bash`（排除 `System32\bash.exe` 这个 WSL 启动器）
3. 从 `git.exe` 位置与 `git --exec-path` 推断同装的 Git Bash
4. Windows 注册表 `SOFTWARE\GitForWindows` 的 `InstallPath`
5. 固定候选路径（`C:\Program Files\Git\bin\bash.exe` 等，含 `LOCALAPPDATA` 下的用户级安装）
6. WSL（`wsl.exe` 存在且 `wsl --list --quiet` 能列出真实发行版才算可用）
7. busybox-w32
8. PowerShell（优先 `pwsh`，回退 `powershell`）

前五步命中即 Git Bash 一类的 POSIX shell。八步全落空时**直接报错**，引导安装 Git for Windows 或设 `STEP_SHELL_PATH`，**不回退 `cmd.exe`**——`cmd` 不认 Unix 语法，兜底到它是「能跑但全错」，比明确报错更难排查。

POSIX 平台不做这套探测，直接用 `$SHELL`，缺省 `/bin/bash`。

按实际生效的解释器，命令会被预处理：

| 解释器 | 命令预处理 | 工作目录 |
|--------|------------|----------|
| Git Bash / MSYS bash | `>NUL` 改写为 `> /dev/null` | 原生 Windows 路径直接传（转成 `/c/` 反而报错） |
| WSL | 同上，外加命令前置 `cd '/mnt/<盘符>/...'` | 传原生 Windows 路径给 spawn，bash 内工作目录靠前置 `cd` 切换 |
| busybox | `>NUL` 改写为 `> /dev/null` | 原生路径 |
| PowerShell | 原样透传 | 原生路径 |

`>NUL` 改写覆盖裸 `NUL`、设备名 `NUL:` 和带引号的 `"NUL"`，不误伤 `NULL`、`nullable` 这类普通词。

探测结果在进程内缓存，命中真实 shell 后只探一次。例外是「一个都没找到」：这种结果只做 30 秒节流而不长期缓存，这样长驻会话里中途装上 Git Bash 能自动生效，无需重启。

生效的解释器还会决定 system prompt 里的语法提示，所以回退到 PowerShell 时模型会被告知改用 cmdlet 语法，而不是继续写 `ls`、`2>/dev/null`。

## 联网工具

### `web_search`

接阶跃星辰官方网页搜索接口，按阶跃平台搜索计价（api 通道按量 / plan 通道消耗 Credit）。

> **endpoint 解析（重要）**：搜索请求的 url 与 key 按「`[search.web]` → `[search]` → 主会话渠道」的优先级解析：
>
> - **配了 `[search]` 段**：搜索走独立配置的 url + key，与主会话用什么模型渠道完全无关。这是推荐做法，见[配置参考](./configuration.md#search-联网搜索)。
> - **没配 `[search]` 段（默认）**：回退到主会话渠道的 `base_url` + `api_key`。此时主会话必须走阶跃渠道，切到非阶跃渠道（其他厂商模型、自建网关）会 404 失败。
> - **子 agent 的搜索跟随主会话的搜索配置**，不跟随子 agent 自己的 `model` 别名。主会话搜索可用时，即使子 agent 绑定了其他渠道的模型，它的 `web_search` / `web_image_search` 也正常。
>
> 内容搜索支持阶跃 api（`/v1/search`）与 plan（`/step_plan/v1/search`）双通道，文搜图仅 plan 通道，详见配置参考。

| 参数 | 类型 | 说明 |
|------|------|------|
| `query` | string，必填 | 检索关键词 |
| `n` | 整数 1–20，可选 | 结果条数，默认 10 |
| `category` | 枚举，可选 | `programming` / `research` / `gov` / `business`；省略则全网 |

返回每条的序号、标题、URL 与摘要（摘要截断到 500 字符）。未配置 API key 时报错，并提示可在 `[search]` 段配置独立的搜索 url 与 key。

接口返回的结果若带完整正文，会写进进程内缓存供 `web_fetch` 复用，并在结果末尾标注 `[Cached N URLs with full content for web_fetch]`。

HTTP 错误按状态码分流，其中 **451 是内容安全审核拦截**（检索词或返回内容未过审），与 key、额度无关；401/403 指向 key 问题，429 指向限流或 Step Plan 额度；404 或连接失败先检查搜索 endpoint 配置是否正确（见上方解析说明）。

### `web_image_search`

接阶跃星辰官方文搜图接口（`POST <base>/step_plan/v1/search-image`），同样走 Step Plan 通道消耗 Credit。

| 参数 | 类型 | 说明 |
|------|------|------|
| `query` | string，必填 | 图片描述，建议中文，也支持英文 |
| `topk` | 整数 1–20，可选 | 图片张数上限，默认 5 |

返回每张图的描述（可直接作 alt）、原图地址、尺寸与来源网页。检索词命中内容审核时明确报「命中内容审核拦截」，提示调整描述。

它不参与网页正文缓存——缓存只服务 `web_search` 与 `web_fetch`。

### `web_fetch`

抓取指定 URL 的正文。

| 参数 | 类型 | 说明 |
|------|------|------|
| `url` | string（需为合法 URL），必填 | 要抓取的网页地址 |

处理顺序是**先查缓存，再走网络**。命中缓存直接返回，不发请求；未命中则本地抓取，成功后写回缓存。返回文本开头会标明内容来源：搜索缓存、页面提取、还是原样透传。

内容处理分两条路：

- **文本类响应原样透传**：`text/*`（除 `text/html`）以及 JSON、JavaScript、XML、RSS/Atom、shell 脚本等 `application/*` 文本类型，直接返回响应体，不进 HTML 解析器。
- **HTML 走正文提取**：先用 Readability 提取，取到标题则以 `# 标题` 开头。Readability 失败或提取为空时回退到 `<article>` → `<main>` → `<body>` 的文本。两条都拿不到有意义内容时报错，并提示该页面可能需要 JavaScript 渲染。

**SSRF 防护**：

- 只允许 `http` / `https`，其他 scheme 直接拒。
- 拒绝私有地址段：`0.0.0.0/8`、`10/8`、`100.64/10`、`127/8`、`169.254/16`、`172.16/12`、`192.168/16`，以及 IPv6 的 `::`、`::1`、`fc00::/7`、`fe80::/10`。
- 拒绝 `localhost` 与 `*.localhost`。
- 域名先做 DNS 解析，**所有**返回地址逐个校验，任一落在私有段即拒绝——防止域名解析到内网。
- 校验通过的地址会被钉给实际连接使用，避免校验与连接之间的解析漂移。
- 重定向**手动逐跳处理**，每一跳都重新做完整安全校验，上限 **10 跳**。
- 响应体上限 **10 MB**，先看 `Content-Length` 预判，读完再按实际字节数复查。
- HTTP 状态 ≥ 400 按错误返回。

### 共享缓存

`web_search` 与 `web_fetch` 共用一份进程内缓存（实现在 `src/tools/webCache.ts`）：

- **TTL 30 分钟**，读取时判过期，过期条目即时删除。
- **容量 100 条**，超出按插入顺序淘汰最旧条目。
- 键是 URL 原文，同 URL 重复写入直接覆盖。
- 条目分两种来源：`search`（搜索接口返回的正文）与 `fetch`（本地抓取提取的正文）。

实际收益是：`web_search` 搜到一批结果后，模型想深读其中某条时调 `web_fetch`，通常直接命中缓存，省掉一次网络往返。缓存是进程级单例，会话切换时清空。

## 交互工具

这三个工具都没有本地副作用，在任何权限档下都直接放行。

### `ask_user`

模型主动向你提问并让你在选项里选择，用于澄清歧义或收集偏好。

| 参数 | 类型 | 说明 |
|------|------|------|
| `questions` | 数组，1–4 项 | 问题列表，前台逐题顺序询问 |

每个问题的字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `question` | string，必填 | 完整问题文本 |
| `header` | string，可选 | 极短分类标签（chip），≤ 12 字符 |
| `options` | 数组，2–4 项 | 候选项，每项含 `label` 与可选 `description` |
| `multi_select` | boolean，可选 | 是否允许多选，默认 `false` |

选项不需要自带「其它」——系统会自动追加自由输入项。推荐项放第一位，`label` 结尾标 `(Recommended)`。

前台同步阻塞等待你回答，答案回喂进对话成为上下文。按 Esc 取消时返回空答案，并按非错误结果告知模型「用户取消了本次提问」，让它基于已有信息继续而不是反复追问。子 agent 没有 UI，调用它会返回「当前上下文不支持向用户提问」。

### `exit_plan_mode`

计划模式下提交执行计划、请求退出。

| 参数 | 类型 | 说明 |
|------|------|------|
| `plan` | string，必填 | 整理好的执行计划（Markdown），列清要做的事、改动文件、顺序与验证方式 |

工具本体不做事，只返回「计划已提交」——真正的动作是宿主拦下这次调用、把计划呈现给你确认。批准后退出计划模式、按正常权限执行；拒绝则把你的反馈回灌让模型修订计划。

它是退出计划模式的唯一途径。计划模式下的权限拦截规则见[交互使用](./interactive.md)。

### `todo_list`

维护当前任务清单，用于跟踪多步骤、跨回合任务的进度。

| 参数 | 类型 | 说明 |
|------|------|------|
| `todos` | 数组，可选 | 更新后的**完整**清单（整体替换）。省略则只读取，传空数组则清空 |

每个条目是 `{ title, status }`，`status` 取 `pending` / `in_progress` / `done`。

读写合一：传 `todos` 整体替换，传 `[]` 清空，不传参数就只读当前清单。清单存在独立 store 里，**不占对话历史**，在 TUI 里以面板呈现。

「恰好一个 `in_progress`」是软约束——更新成功后的返回里附一条提醒，但不做强制校验，模型可以违反。

## 通用机制

以下机制对所有工具生效，包括动态注册的 MCP 工具。

### 入参校验与 schema 生成

每个工具用一份 zod schema 同时承担两件事：运行时校验入参，以及自动生成发给模型的 JSON Schema。参数的类型、范围、可选性、描述文字都只写一遍，不存在「schema 说一套、代码校验另一套」的漂移空间。

调用前先 `safeParse`，失败则返回 `工具 <name> 入参校验失败：<原因>`，不进 execute。

### 结果强制配对回灌

agent 主循环的硬性约定：**每个 `tool_use` 必须配一个 `tool_result`，绝不出现孤立 `tool_use`**。孤立的工具调用会让对话历史不合法，后续请求直接失败。

保障手段是把工具返回值当作信任边界处理（`src/tools/index.ts` 的 `coerceToolResult`）：

- 合法结果对象原样通过。
- 返回裸字符串的，包装成成功结果。
- 返回 `undefined`、原始值、畸形对象的，一律转成合成的错误结果。

再加上未知工具名、入参校验失败、execute 抛异常三条路径也都转成错误结果，`executeTool` 因此**永不抛出**——无论工具内部发生什么，主循环总能拿到一个可回灌的结果。

### 工具报错不抛异常

工具遇到问题返回「失败结果」（带 `isError` 标记回灌），而不是抛异常终止回合。文件不存在、`old_string` 不唯一、正则非法、命令退出码非 0、搜索被审核拦截——这些都以错误文本回到模型手里。

这是有意的设计：错误信息本身是给模型的输入。所以错误文案写得具体且带下一步指引，比如 `old_string` 不唯一会报出实际出现次数并建议补上下文或设 `replace_all`。模型据此自纠，不需要你介入。

### 并行执行

一轮里模型可能发出多个工具调用。调度器（`src/agent/toolScheduler.ts`）不按固定串行跑，而是按**资源冲突**决定谁能并发。

每个工具声明自己这次调用要碰什么资源（`src/tools/access.ts`）：

| 声明 | 含义 | 典型工具 |
|------|------|----------|
| `none` | 无本地副作用 | `web_search`、`web_fetch`、`web_image_search` |
| `read` + 路径 | 读文件或目录 | `read_file`、`list_dir`、`glob`、`grep` |
| `write` + 路径 | 写文件 | `write_file`、`edit_file` |
| `all` | 完全独占 | `bash`，以及所有未声明的工具 |

冲突判定规则：任一边是 `all` 必冲突（连 `none` 也不放行）；`none` 与其余都不冲突；读读不冲突；至少一边是写时，仅当路径相等或按目录边界前缀重叠才冲突（`/a/b` 与 `/a/bc` 不算重叠）。

于是三个 `read_file` 会并发跑，两个改同一文件的 `edit_file` 自动串行，`bash` 独占一轮不与任何工具并行。**未声明资源的工具按 `all` 处理**——新工具漏了声明，退化成安全的串行行为而不是并发事故。

调度不设数字上限：一轮的工具数量被模型输出长度天然约束，冲突模型才是真边界。只有 `spawn_agent` 额外受子 agent 并发槽位限制（背后是真实 API 配额）。

无论实际执行顺序如何，**结果按模型调用的原始顺序回灌**。同一资源上排队时按调用顺序先到先得，后来的不插队。

### 权限门控

工具按风险分三类（`src/agent/permission/mode.ts`）：

| 类别 | 工具 | 判定 |
|------|------|------|
| 只读 / 无副作用 | `read_file`、`read_media`、`list_dir`、`glob`、`grep`、`web_search`、`web_fetch`、`web_image_search`、`spawn_agent`、`exit_plan_mode`、`ask_user`、`todo_list` | 任何权限档都直接放行 |
| 写文件 | `write_file`、`edit_file` | `manual` 需确认，`auto` / `yolo` 放行 |
| 执行命令 | `bash` | `manual` / `auto` 需确认，`yolo` 放行 |
| 其他（MCP 与插件工具） | — | 保守起见需确认 |

几点说明：`spawn_agent` 在白名单里是因为「派生」这个动作本身无害，子 agent 内部的写与执行各自过权限；`ask_user` 只是收集偏好，计划模式下也用它澄清需求。`read_media` 没有本地副作用，归入只读行后计划模式下看界面截图这类纯读调查不再被硬拦。本会话里批准过的工具名会被记住，后续同名调用直接放行。

判定只产出「放行」或「需确认」两种结果，**拒绝只来自你在确认对话里的选择**。计划模式是叠加在权限档之上的独立维度，开启后写类与执行类工具被硬拦，只放行只读调查与 `exit_plan_mode`。

三档权限的切换方式、确认对话的操作、计划模式的进入退出，见[交互使用](./interactive.md)。
