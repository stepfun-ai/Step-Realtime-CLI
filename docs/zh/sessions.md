# 会话管理

本页讲会话的保存、恢复、分叉、压缩与回顾，以及非交互输出格式。

## 持久化

每次对话自动保存为快照，存在 `~/.step-code/sessions/` 下、按工作目录分桶——在 A 项目目录启动时只会看到 A 项目的会话。会话标题初始从首条消息自动派生；第一轮回答完成后，会用当前模型异步生成一次语义标题覆盖派生值（失败则保留派生值，不影响会话）。已重命名（`r`）或标题被外部改过的会话不会被覆盖。

## 续接与恢复

```bash
step --continue        # 续接当前目录最近一次会话
step -c -p "继续"      # 非交互模式下续接
step --resume          # 打开交互式会话选择器（↑↓ 浏览、打字搜索、Enter 恢复）
step --resume <id>     # 直接恢复指定会话
step --session <id>    # 同 --resume <id>
```

无头管理：

```bash
step sessions list          # 列出当前目录的会话
step sessions show <id>     # 查看会话内容
step sessions delete <id>   # 删除
step sessions rename <id> <名字>   # 重命名（等价于选择器里按 r）
```

交互界面内：`/resume` 不带 id 弹出交互式会话选择器，`/resume <id>` 直切指定会话，`/sessions` 只读列出会话，`/new` 开新会话。

### 交互式会话选择器（命令行 `-r` 与界面内 `/resume` 通用）

- **↑↓** 移动高亮，分页展示（每页 10 条，翻页可看完全部历史会话，不再有条数上限）。
- 直接**打字即增量搜索**（匹配标题与首条消息，空格分词 AND），Backspace 逐字删。
- **Enter** 恢复高亮会话，**Esc** 取消。
- **Delete / Ctrl+D** 删除高亮会话，进入 `[y/N]` 二次确认（本地文件不可逆）；当前正在使用的会话不可删除。列表中当前会话标「当前」。
- **r** 重命名高亮会话：进入编辑态输入新名字，Enter 确认（空名即清除自定义名）。改名不刷新最近使用时间，不会把会话顶到列表最前；展示优先级为 自定义名 > 标题 > id，自定义名参与搜索。命令行 `step sessions rename <id> <名字>` 等价。

### 会话级状态持久化

以下状态随会话保存，关掉重开恢复会话时一并读回：对话历史、TODO 清单、goal 快照、**权限模式**（manual/auto/yolo）与**模型**。即会话里切了 `/yolo` 或 `/model`，下次恢复该会话仍是当时的模式与模型（命令行 `--yolo`/`--auto`/`--model` 显式指定时优先覆盖）。旧会话快照缺这些字段时回退启动默认。

### 恢复时重放历史内容

恢复会话（`step -r`、`--continue` 或界面内 `/resume`）时，历史对话会重新渲染到终端——用户输入、助手回复、思考块、工具调用与结果都按原顺序铺开，和实时对话看起来一致。工具调用会显示当时的执行状态与结果，模型内部注入的提醒消息不展示。

底部会给出双口径提示，例如「已恢复会话 X（23 轮 · 302 条消息）」：

- **轮次**：按你的每次真人输入切分，一次输入到下次输入前的所有往返算一轮，是符合直觉的"聊了几个来回"。
- **条消息**：底层存储的真实消息条数（一条助手回复可能带多个工具调用、一批工具结果又打包成一条），用于上下文与压缩等系统逻辑。

长会话默认只重放**最近 15 轮**，更早的在顶部提示「更早的 N 轮历史已折叠」。这只影响终端里重新绘制多少内容，完整历史仍全部载入、继续对话时模型能看到。

## 分叉（fork）

`/fork` 从当前最新点复制整个会话为新会话，源会话不动。适合"从这里开始想试另一个方向，但不想丢掉现在的进度"。

## 上下文压缩

对话变长接近上下文上限时自动压缩：先微压缩（清旧工具结果正文），仍超再做全量 LLM 摘要。触发条件可在 `[compaction]` 段配置。手动压缩用 `/compact`。

摘要生成后要过质量校验（非空、信息量达到被压缩量的一定比例、不含历史渲染标记），不合格会缩小输入重试，连续失败则放弃本次压缩、完整保留历史。详见 [配置参考的 `[compaction]` 段](configuration.md#compaction-上下文压缩)。

完整的原始历史不受压缩影响：每个会话另存一份 append-only 全量日志（`<id>.full.jsonl`），供 `/reflect` 使用。

## 回顾（/reflect）

`/reflect` 分段遍历完整对话历史，提炼可复用的方法论经验打印出来。长会话收尾时跑一次，把"这次是怎么做成的"沉淀下来。非交互等价物：`step --reflect -c`。

## 导出

`/export-debug-zip` 或 `step export-debug-zip [sessionId]` 导出会话调试包（zip），排查问题时使用。

## 非交互输出

`-p` 模式下：assistant 文本走 stdout，工具调用和错误走 stderr，可以直接进管道。加 `--output-format stream-json` 则每个事件输出一行 JSON，供程序消费（比如接进自己的脚本或 CI）。

事件信封契约、全部事件类型、版本与兼容规则见 [stream-json 事件流](./stream-json.md)。


## 子 agent 会话

子 agent（`spawn_agent` 派生）每次执行都会落盘为独立子会话，存在会话桶的 `subagents/` 子目录下：`<id>.json` 快照 + `<id>.full.jsonl` 全量日志 + 运行期 `<id>.lock` 活跃锁。子会话不进主会话列表，不会污染 `/resume` 与 `--continue`。

无头管理：

```bash
step subagents list          # 列出当前目录的子会话（类型 · 状态 · 父会话）
step subagents show <id>     # 完整回看子 agent 历史
step subagents delete <id>   # 删除（正在运行、持活跃锁的会被拒绝）
```

界面内 `/resume` 弹出的选择器只列主会话，选中直接恢复该会话（详见上节交互式选择器说明）。子 agent 会话由 `/agents` 命令独立管理：列出当前会话派生的子 agent 会话，选中可下钻查看该子 agent 的完整历史（只读，不切换当前会话）。**注意：下钻查看是只读的，不能在子 agent 会话里继续对话**——让子 agent 在已有工作基础上继续，走 `spawn_agent` 工具的 `resume` 参数（由模型侧发起）。通过 `step subagents list` / `step subagents show <id>` 可无头访问。

**续跑**：`spawn_agent` 工具支持 `resume=<子会话 id>` 参数，从历史断点继续执行——新指令追加为一条 user 消息，不替换已有历史；已完成与失败的子会话都可续跑，唯一限制是目标会话当前没在运行（持活跃锁会被明确拒绝）。resume 不是新派生，不占单会话派生配额。工具返回串里带有子会话 id，模型后续可自行引用续跑。

**崩溃安全**：若上次执行断在工具调用中途（最后一条助手消息带着没有结果的工具调用），续跑前会自动补一条「上次执行被中断」的工具结果，保证回灌的历史可以安全发给模型。

**留存策略**（`~/.step-code/config.toml`）：

```toml
[subagent.retention]
delete_with_parent = true   # 删主会话时连带删其子会话（默认开）
max_sessions = 0            # 子会话数量上限（超出删最旧），0 = 不限
ttl_days = 0                # 子会话过期天数，0 = 不过期
```

默认不主动删除任何子会话，唯一的自动回收是随主会话级联删除。`max_sessions` 与 `ttl_days` 的清理只在进程启动时执行一次（只扫当前工作目录的子会话），运行期间不触发。所有清理路径都会跳过正在运行的子会话。
