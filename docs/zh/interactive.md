# 交互使用

本页讲交互界面的日常使用：斜杠命令、快捷键、权限模式与计划模式。

## 界面结构

pi-tui 终端界面：顶部欢迎框，中间是会话流（你的输入、模型回复、工具调用卡片），底部两行状态栏——第一行是权限模式（manual 绿 / auto 黄 / yolo 红）、模型名、状态、后台任务徽章 `bg:N`、自主目标徽章 `goal ● 用时 · 轮次`、当前路径（过长时缩短）；第二行是快捷键提示和 context 用量（真实 token 百分比）。后两个徽章按需出现，没有后台任务或目标时不占位。

模型正在工作时输入文字不会丢：进入发送队列，回合结束自动逐条发出，输入框上方有队列预览。

忙碌时输入框上方显示一行状态：`⠋ 状态词… (12s · ↓ 585 tokens)`——转圈 spinner + 已用时间 + 本轮产出 token（估算），下面一行是随机操作提示（Tip）。spinner 独占一行、定宽，不与你的输入挤在一起。

### 会话流与滚动

历史直接翻终端原生 scrollback（滚轮/滚动条），随时可翻、不会被刷新打断。已定稿的内容只写一次、永久落在历史里；正在生成的长内容只显示尾部，顶部压一行「↑ 已隐藏 N 行」，输出完整后全文自然落入历史——这是刻意的取舍：流式期你的注意力在最新几行，而翻历史永远完整、不丢不跳。

工具输出默认折叠为一行摘要（「N 行输出 · Ctrl+O 展开」），定稿入历史后恒为折叠摘要，保证历史紧凑。Ctrl+O 打开全屏查看器：最近的可展开工具输出与思考内容按轮次分组、完整渲染（Markdown/diff 上色/思考斜体），↑↓ 或 `k`/`j` 滚行、PgUp/PgDn 翻屏、←/→ 切轮、Home/`g` 跳顶、End/`G` 跳底、Esc/`q` 或再按 Ctrl+O 关闭；查看器有独立滚动，不影响终端 scrollback。

恢复会话（`step -r` / `/resume`）时，历史对话会重新渲染到终端，和实时看起来一致；长会话默认只重放最近若干轮，更早的在顶部提示已折叠。详见[会话管理](./sessions.md#恢复时重放历史内容)。

## 斜杠命令

敲 `/` 弹出命令菜单，↑↓ 选择（循环回卷）、Tab 补全、Enter 执行、Esc 关闭并清空输入框。匹配规则：前缀匹配优先；恰好 2 个字符时额外启用子序列回退，覆盖 `cp` → `compact` 这类缩写。菜单一屏 6 条，超出窗口化滚动并显示 `(当前/总数)`。

全部 26 条命令（下表 27 行——`/skill reload` 单独列出，它是 `/skill` 的子命令而非独立命令）：

| 命令 | 作用 |
|------|------|
| `/help`（`/?`） | 列出全部命令 |
| `/model [别名]` | 无参打开交互式选择器（未登记 `[models]` 时只显示当前模型），带参直切 |
| `/think [档位\|off]` | 思考深度。无参打开档位选择器，带参直切，`off` 本会话停发 thinking 字段 |
| `/permission [manual\|auto\|yolo]` | 无参显示当前档位，带参切换（非法值等同无参，只显示不切） |
| `/yolo` | 直接切到 yolo（全部放行） |
| `/auto` | 直接切到 auto（写放行，bash 需确认） |
| `/plan` | 开关计划模式（会话级状态，切换即落盘） |
| `/provider [名称]` | 无参打开渠道管理面板（切换/新增/删除）；`list` 出静态文本列表；带参直切（自定义渠道 id 优先于预设名）；`/provider add` 唤起新增渠道向导（手动录入或 models.dev 目录导入） |
| `/goal [pause\|resume\|cancel]` | 无参或 `status` 出目标状态面板，带子命令控制目标状态 |
| `/team <子命令>` | 多 agent 团队模式：`init [--dir <路径>]` 初始化（`--dir` 放仓外支持跨仓）、`status` 看任务清单、`exit` 退出（状态保留可重进）、`teardown [force]` 收尾清工作间 |
| `/loop`（别名 `/cron`） | 列出定时/循环任务及下次触发时间（只读；创建由模型调 `cron_create`） |
| `/fork` | 从当前点分叉出新会话副本，原会话不动 |
| `/new` | 开新会话（清空上下文、任务清单、计划模式、动态工具与思考档位覆盖） |
| `/compact` | 手动压缩上下文，打印压缩前后 token 数 |
| `/history [N]`（别名 `/undo`） | 无参打开本会话输入历史面板（Enter 回退到该轮并取回原文重发，Tab 仅取回文本）；带参直接撤销最近 N 轮，不开面板 |
| `/reflect` | 回顾完整会话历史，提炼可复用方法论并打印；产出同时注入会话流——可直接说「记住第 N 条」让 agent 沉淀到记忆目录 |
| `/agents` | 列出当前会话派生的子 agent 会话，选中可下钻只读回看该子 agent 的历史 |
| `/export-debug-zip` | 导出会话调试包（会话正文 + 脱敏配置 + 运行日志） |
| `/usage [--all]` | 按模型分组展示本会话的 token 用量与缓存命中率；`--all` 汇总本工作目录全部会话（含无快照的崩溃残留会话）。只读，忙碌时也可即时执行 |
| `/resume [id]`（别名 `/sessions`） | 无参打开交互式会话选择器（只列主会话），带 id 直接恢复 |
| `/lang [zh\|en]` | 无参显示当前语言，带参切换中英文界面并写回 `config.toml` 的 `language` |
| `/memory [on\|off]` | 记忆观察池：无参列出当前观察（全局 + 项目两层，含索引用量与待修复文件）；`on`/`off` 开关并写回 `config.toml` 的 `[memory] enabled`。默认关闭；观察不直接生效，定期回顾确认后才晋升规范层 |
| `/mcp` | 查看 MCP server 连接状态与工具数 |
| `/skill [名称] [参数]` | 无参打开交互式技能选择器（输入过滤，↑↓ 选择，Enter 激活，Esc 取消），带参手动激活 |
| `/skill reload` | 强制重扫技能目录（会话中改动 SKILL.md 后即时生效；回合边界也会自动检测） |
| `/reload` | 热重载 `config.toml` |
| `/plugin` | 管理插件：`install / list / enable / disable / remove / info` |
| `/tasks` | 打开后台任务浏览器（列表 + 输出预览 + 停止运行中任务） |
| `/exit`（`/quit`、`/q`） | 退出 |

插件可以注册自己的命令，形式为 `/<插件id>:<命令名>`，参数展开后作为消息提交。

### 模型工作时的命令分流

模型正在跑时敲命令不会全部排队，按「是否改动当前回合依赖的状态」分两路：

- **即时执行**：`/help`、`/goal`、`/team`、`/loop`、`/sessions`、`/agents`、`/lang`、`/mcp`、`/plugin`、`/tasks`，以及 `/model`、`/provider`、`/permission`、`/skill`、`/think` 的**无参查询形态**。未知命令也即时提示，不用等回合结束。
- **排队到回合边界**：其余全部命令（改动历史、会话、模型、权限、plan 或触发退出的），与普通消息一样进发送队列。

`/model` 无参在忙碌时不开选择器，只提示；`/think` 无参忙碌时退化为文本档位清单；`/fork`、`/export-debug-zip` 忙碌时直接拒绝并提示稍后再试。

### `/history` 回顾与回退（别名 `/undo`）

无参打开本会话输入历史面板：按「真人输入」切分的轮次逐条列出（系统注入与静默轮不算），↑↓ 浏览，Enter 回退到该轮——上下文回退到该轮起点之前（连同这些轮产出的模型回复与工具结果），转录区同步截断，任务清单与计划模式按每轮快照回滚，同时把该轮输入原文填回输入框、可编辑后重发。Tab 只取回原文到输入框、不回退，Esc 关闭。

- **不回滚代码改动**。文件已经写下去了，回退只管对话状态。
- **压缩点之前不可回退**。`/compact` 之后旧轮已被折叠为摘要，不再算作可回退的轮起点；压缩同时清空快照栈。
- `/new`、`/resume`、`/fork` 也会清空快照栈。此后回退仍能回退上下文，但任务清单与计划模式保持现状（无快照可恢复）。
- `/history <正整数>`（即旧 `/undo N` 用法）跳过面板直接撤销最近 N 轮，不取回文本；N 超过可回退轮数时回退到最早一轮为止。
- 与输入框 ↑↓ 回溯的输入历史（跨会话草稿）是两个数据源：面板回顾的是本会话已发送的轮次。

### `/reload` 热重载配置

重新读取 `config.toml`，不重启进程、不动会话历史。执行后打印字段级 diff（`+` 新增 / `-` 删除 / `~ 旧 → 新`），`api_key` 只报变更不回显内容。

- **失败原子性**：解析或校验出错时旧配置整体保留，一步不落，只报错。
- provider 视情况重建：当前模型绑定的别名仍在则按新配置重建（下一轮请求生效）；别名被删或无法解析、重建失败时沿用旧 provider 并提示。构造参数无变化时跳过重建。
- `language` 变化即时切界面语言。
- 少数字段启动时一次性固化，diff 行会追加「需重启生效」：`agents_paths`、`agents_md_max_bytes`、`background.bash_task_timeout_s`。

## 快捷键

| 按键 | 作用 |
|------|------|
| Esc | 见下方「Esc 的分层语义」 |
| Ctrl+C | 生成中输入框优先：输入框有内容时只清空输入框、**不中断回合**，输入框为空时才中断当前回合（要在有草稿时中断，先按一次清空再按一次）。空闲时第一次按清空输入框并进入「再按一次退出」预备态（5 秒无第二次自动取消），第二次按退出 |
| Ctrl+B | 将当前全部前台 bash 任务转后台：进程继续运行，工具调用立即返回后台任务 id，终态通知与状态栏 `bg:N` 徽章同步可见。前台任务改为进程启动即登记，用户主动转后台与前台超时自动转后台走同一条释放通道；中断（Esc / Ctrl+C）不再误杀已转后台的进程 |
| Ctrl+O | 打开全屏查看器：最近的可展开工具输出与思考内容按轮次分组完整渲染，↑↓ 或 `k`/`j` 滚行、PgUp/PgDn 翻屏、←/→ 切轮、Home/`g` 跳顶、End/`G` 跳底、Esc/`q`/Ctrl+O 关闭（已定稿入历史的输出在会话区恒为折叠摘要） |
| Alt+V | 从剪贴板粘贴图片：在输入框末尾追加占位符 `[image #1 (宽×高)]`，可像普通文字一样编辑删除，提交时展开为图片。仅空闲时可用。Windows 用系统自带 PowerShell；macOS 用系统自带 osascript；Linux 需装 `xclip`（X11）或 `wl-clipboard`（Wayland），未装时会提示 |
| ↑ / ↓ | 输入框空时回溯发送历史（bash 式草稿暂存）；菜单可见时归菜单选择；忙碌且输入框为空时 ↑ 优先从发送队列尾部取回一条回填编辑 |

弹层激活时（模型选择器、思考档位选择器、历史回顾面板、会话选择器、渠道管理面板、新增渠道向导、后台任务浏览器、审批面板、提问面板、计划确认框）全部按键交给该弹层，上表的全局键暂时让位——Ctrl+O 也不例外：其他弹层开着时按 Ctrl+O 会被忽略；查看器自身打开期间则接管全部按键。

### Esc 的分层语义

Esc 按以下优先级逐层判定，弹层永远优先：

1. **弹层激活时**：Esc = 取消 / 拒绝，由弹层自己消费。计划确认框里 Esc 等同 `n`（拒绝并把反馈交回模型修订）。
2. **斜杠菜单可见时**：Esc 关菜单并清空输入框，不中断回合。菜单关掉后下一次 Esc 才生效。
3. **生成中**：中断当前回合，历史保留。发送队列非空时，回合结束会自动续发。
4. **空闲且发送队列非空**：把队列内容合并回输入框交还给你编辑，队列清空。
5. **空闲、队列空、输入框空、存在可回退消息**：第一次 Esc 进预备态（5 秒无第二次自动取消），第二次 Esc 回退上一条用户消息及其之后的历史，并把原文填回输入框重编辑。

### 输入框编辑键

输入框支持 readline 风格的光标移动与删除键。手敲时 Enter 即提交、无法输入换行；从剪贴板粘贴的多行文本会保留换行并按行显示（Windows 剪贴板的 `\r\n` 自动归一为 `\n`）：

| 按键 | 作用 |
|------|------|
| Home / Ctrl+A | 光标到行首 |
| End / Ctrl+E | 光标到行尾 |
| ← / → | 左右移动一个字符 |
| Ctrl+← / Alt+B | 按词左移 |
| Ctrl+→ / Alt+F | 按词右移 |
| Backspace | 删除光标前一个字符 |
| Delete | 删除光标处字符 |
| Ctrl+W | 删除前一个词（连同前面的空白） |
| Ctrl+U | 删到行首 |
| Ctrl+K | 删到行尾 |

光标按 Unicode 码点计算，CJK 与 emoji 不会被切成半个字符。

## 权限模式

三档梯度，启动默认 manual：

- **manual**：写文件（`write_file` / `edit_file`）与执行命令（`bash`）都要逐项确认。
- **auto**：写文件放行，`bash` 仍需确认。
- **yolo**：全部放行，适合沙箱或你完全信任的任务。

只读与非破坏性工具在任何档位下都直接放行，从不打扰：`read_file`、`read_media`、`list_dir`、`glob`、`grep`、`web_search`、`web_fetch`、`web_image_search`、`spawn_agent`、`exit_plan_mode`、`ask_user`、`todo_list`。派生子 agent 本身无害，子 agent 自己的写与执行各自过一遍权限。未在上述任何清单里的工具——MCP 与插件带来的工具——在 manual / auto 下一律需确认。

选过「本会话允许」的工具名在本会话内直接放行，直到 `/new` 或换会话。

### 确认面板

manual / auto 下需要确认时弹出竖向编号列表，四个选项：

| 按键 | 作用 |
|------|------|
| ↑↓ + Enter | 移动选中（循环回卷）并确认 |
| 1 / 2 / 3 | 直选并立即执行：允许本次 / 本会话允许 / 拒绝 |
| 4 或 f | 进入「拒绝并写评论」态 |
| y / a / n | 等价于 1 / 2 / 3（保留肌肉记忆） |
| Esc | 任何时刻直接拒绝（不带反馈） |
| Ctrl+E | 展开/收起待写入内容预览（仅内容超出显示上限时有意义） |

选「拒绝并写评论」后该行变成内联输入框，敲完 Enter 把原因作为工具结果回灌给模型；此时 ↑↓ 退出评论态并移动选中，Esc 仍是直接拒绝。`bash` 命令命中危险模式时，命令摘要上方会渲染红色加粗警告行。

非交互模式（`-p`）下写操作需要 `--auto` 或 `--yolo`，否则会被拒绝。

## 计划模式

`/plan` 开启后，权限层硬拦所有写类与执行类工具（拦截原因作为工具结果回灌模型），只放行只读调查与 `exit_plan_mode`。模型完成调查后调 `exit_plan_mode` 提交计划，弹出 `Ready to code?` 确认框：`y` 批准并执行，`n` 或 Esc 拒绝并把反馈交回模型修订。

批准后自动关闭计划模式并恢复进入前的权限档。它是独立维度，叠加在权限模式之上：比如 manual + plan 表示「先出计划，批准后逐步确认执行」。适合改动范围大、想先看方案再动手的任务。再输入 `/plan` 可提前关闭。

计划模式是会话级状态，切换即落盘，恢复会话时读回；`/new` 时清零。

## 会话选择器

`/resume` 无参（或命令行 `step -r` 不带 id）打开交互式会话选择器：↑↓ 移动（**循环回卷**，与渠道管理面板到头停住的 ↑↓ 不同；分页翻页看完全部会话）、直接打字模糊搜索、Enter 恢复、Esc 取消，Delete/Ctrl+D 删除高亮会话（`[y/N]` 二次确认，当前会话不可删），按 r 重命名高亮会话（改名不影响排序，命令行 `step sessions rename <id> <名字>` 等价）。`/resume <id>` 文本直切。`/sessions` 是 `/resume` 的别名，行为完全相同；只读列出会话走命令行 `step sessions list`。当前目录没有历史会话时只提示、不开选择器。权限模式与模型随会话持久化，恢复时读回。详见[会话管理](./sessions.md#交互式会话选择器命令行--r-与界面内-resume-通用)。

## 切换模型

`/model` 无参会打开交互式选择器（前提是你在 config.toml 里用 `[models]` 登记了别名，见[配置参考](./configuration.md)）：

- 单层扁平列表，每行显示模型显示名（左列）+ 所属渠道名（右列灰色），当前生效项标 `← 当前`。
- ↑↓ 移动；直接敲字符做模糊过滤（匹配别名/显示名/渠道名），Backspace 删过滤字；Enter 确认、Esc 取消（有过滤词时先清词）。
- 模型正在工作（busy/streaming）时拒绝切换并提示。
- 当前会话已有历史时，选择器顶部会警告「切换模型会使已有 prompt cache 失效，`/new` 开新会话可避免额外 token 消耗」。

`/model <别名>` 是文本直切，跳过选择器。两种方式确认后都会按别名的合并配置重建 provider，上下文窗口随之跟随，状态栏显示新模型的显示名。确认后会把 config.toml 顶层 `model` 一并更新为所选别名，下次启动新会话即沿用（`step --model` 命令行覆盖与 `/resume` 恢复旧会话两种情况不写回）。

**Shift+Enter 仅本会话切换**：在选择器里按 Shift+Enter 确认模型切换但不写回 config.toml——适合「这轮试试别的模型，下次还是用原来的」的场景。Enter 是「切换并设为默认」，Shift+Enter 是「切换仅本会话」。

`/think` 控制思考深度（仅 anthropic 协议且已启用 `[thinking]` 的渠道可用）：无参打开档位选择器（会话忙时退化为文本列表），`/think <档位>` 直切，`/think off` 本会话不再发送 thinking 字段。档位表来自 `[thinking.levels]`（缺省 low/medium/high = 1024/4096/32000），状态栏模型名旁显示当前档位。切换只影响当前会话，不写回 config.toml（持久化用 `default_level`）；会话已有历史时切换会提示 prompt cache 失效。切到的档位在当前 `max_tokens` 下正文余量不足时会给出警告，但不硬拦。

## 切换服务商

`/provider` 无参打开渠道管理面板（会话忙碌时退化为提示，不开面板）：

- 列表 = config.toml `[providers]` 自定义渠道 + 内置预设的合并视图（自定义渠道与预设同名时自定义优先，预设独有行标「内置」），每行显示 id、type、base_url 与别名数，当前生效渠道行尾标 `← 当前`。
- ↑↓ 移动（**到头到尾停住，不循环回卷**——这点与会话选择器的循环 ↑↓ 不同）；Enter 在渠道行上即切换到该渠道，在末尾 `[+ 新增渠道]` 行上（或按 `a`/`A`）进入新增向导；`d`/`D` 删除自定义渠道（内置预设不可删）；Esc 关闭。新增与删除键位大小写都接受。
- 删除会先落到内联 `[y/N]` 确认态，该态**只认 `y`/`n`/Esc**（大小写都收），其余按键全被吞掉——刻意的防误删设计，确认框开着时按 ↑↓ 不会顺手挪走选中行。
- 切换语义与 `/model` 选择器同一条路径：自定义渠道切到它按配置文件顺序的第一个模型别名（重建 provider、上下文窗口跟随、默认模型指针落盘）；渠道下无别名时不切换并提示。预设行走预设重建（见下表）。

`/provider list` 保留无参时代的静态文本输出（当前服务商 + 各自定义渠道的 id/type/base_url/别名数），供 print 模式与脚本场景使用。

`/provider <id>` 文本直切：先按自定义渠道 id 匹配（同上切换语义），再按内置预设名匹配，都不命中时报错并列出全部可用渠道。预设按内置定义重建 provider，下一轮请求生效：

| 预设 | 协议 | 说明 |
|------|------|------|
| `stepfun` | Anthropic Messages | 默认，`base_url` 不带 `/v1` |
| `anthropic` | Anthropic Messages | 无预设模型，切过去后需用 `/model` 指定 |
| `openai` | Chat Completions | `base_url` 带 `/v1` |
| `openai_responses` | Responses | `base_url` 带 `/v1`，支持工具调用；阶跃侧目前仅 `step-3.7-flash` 开放该协议 |

预设自带默认模型时一并切过去，否则提示用 `/model <名称>` 指定。按预设重建后会断开与 `[models]` 别名的绑定（渠道与模型都可能变），后续 `/reload` 不再按别名路径重建 provider。未知服务商名只提示可用列表、不做改动；重建失败时保留原 provider 并报错。

### 删除渠道

面板里 D 删除的是 config.toml 里的自定义渠道：确认后把 `[providers.<id>]` 整节与它名下的全部 `[models.<别名>]` 整节一并摘除（顶层 `model` 指针若指向被删别名也一并清除），写前自动时间戳备份、写完自动 `step doctor config` 校验、失败回滚。删除当前生效渠道时本会话的 provider 实例在内存中继续可用，重启或切换后失效；删除后 `/reload` 让配置全面生效。

### 新增渠道（/provider add）

`/provider add` 唤起新增渠道向导，不用手改配置文件：手动录入路径逐项填写渠道、凭据与首个模型别名（含 capabilities 多选）；目录导入路径从 models.dev 模型目录选供应商，端点、模型别名、窗口与能力按目录元数据自动预填，只需补 API key。写入在 config.toml 末尾追加 section（注释与已有内容不动，自动备份 + 校验，失败回滚）。新增成功后配置自动刷新，并直接拉起模型选择器（预选到新渠道的 tab）让你设默认模型——Esc 只是「不设默认」，渠道与模型已落盘不撤销。详见[配置文件的 /provider 渠道向导](./configuration.md#provider-渠道向导)。

## 推理过程显示

Step 3.x 系列是恒思考模型，响应会带思考过程。TUI 无条件渲染它：

- **流式期**：状态行显示「思考中…」加尾部数行滚动预览，暗色，不进正式会话流。
- **无可见思考文本时**：有些模型的思考块只回签名、不回思考正文。此时状态行在整个思考块期间只显示一行「思考中…」（没有滚动预览），思考块结束即收起——把「模型在闷头想」和「请求卡死」区分开。忙碌态 spinner 的随机状态词已改为中性的「处理中/推进中/…」，不再无条件声称模型在思考。
- **完成后**：落一个暗色斜体折叠块，最多显示前 5 行，超出折叠为「…（共 N 行）」。

是否让模型**主动发送**思考请求字段、以及思考预算，由 config.toml 的 `[thinking]` 段控制（见[配置参考](./configuration.md)）；但无论是否发送，恒思考模型的响应都可能带思考块，渲染始终生效。非交互 `-p` 模式下思考内容不进 stdout，保持输出可管道。

## 插件管理

`/plugin` 管理 `~/.step-code/plugins/` 下的插件：

| 子命令 | 作用 |
|--------|------|
| `/plugin install <目录>` | 从本地目录安装（复制到插件目录，重装即覆盖更新） |
| `/plugin list` | 列出已安装插件及启停/错误状态 |
| `/plugin enable <id>` / `disable <id>` | 启用 / 停用插件 |

## 命令行参数

```bash
step                          # 交互式（进 TUI 界面，默认 manual 权限）
step -p "在 src 下找出所有 TODO"          # 非交互：执行单条指令后退出
step --yolo -p "重命名 a.txt 为 b.txt"    # --yolo 全放行 / --auto 写放行（非交互写操作需要其一）
step --continue -p "继续上次的任务"       # 会话续接（-c）
step --session <id>                     # 恢复指定会话
step --resume                           # 打开交互式会话选择器（-r [id]）
step --provider anthropic -p "..."      # 切换服务商预设
step --model step-3.7-flash -p "..."   # 指定模型
step -C /path/to/project -p "..."       # 指定工作目录
step --output-format stream-json -p "..."   # 每事件一行 JSON
step sessions list                      # 无头子命令：会话管理
step doctor config [path]               # 校验 config.toml（退出码 0/1）
step export-debug-zip [sessionId]       # 导出调试包
```

| 参数 | 说明 |
|------|------|
| `-p, --print <prompt>` | 非交互执行单条指令 |
| `-y, --yolo` / `--auto` | 权限模式：全放行 / 写放行 |
| `-c, --continue` | 续接当前目录最近会话 |
| `-r, --resume [id]` | 恢复会话（无 id 时开选择器） |
| `--session <id>` | 恢复指定会话 |
| `--provider <name>` | 服务商预设（stepfun / anthropic / openai / openai_responses） |
| `--model <name>` | 模型名 |
| `-C, --cwd <dir>` | 工作目录（所有相对路径的基准） |
| `--output-format <fmt>` | 非交互输出格式：`text`（默认）或 `stream-json` |
| `--reflect` | 非交互跑 /reflect（配合 `-c` / `--session`） |
| `-V, --version` / `-h, --help` | 版本号 / 帮助 |

无头子命令（不进 TUI）：`step sessions list`、`step sessions show <id>`、`step sessions delete <id>`、`step sessions rename <id> <名字>`、`step doctor config [path]`、`step export-debug-zip [sessionId]`。`doctor config` 与 `export-debug-zip` 都在读配置之前执行，配置坏了也能校验、也能导出调试包。

## 非交互模式

```bash
step -p "指令"                        # 执行完退出，结果走 stdout，工具/错误走 stderr
step --yolo -p "重命名 a.txt 为 b.txt"
step -p --output-format stream-json "..."   # 每事件一行 JSON，供程序消费
```

非交互模式可进管道：`step -p "总结这个文件" < README.md`，assistant 输出在 stdout，可直接接下游命令。

要用程序消费运行过程（事件信封、全部事件类型、版本兼容规则），见 [stream-json 事件流](./stream-json.md)。
